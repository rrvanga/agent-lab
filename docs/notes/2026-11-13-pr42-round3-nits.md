## What the gate found (round 1 — verdict APPROVE, three NITs)

1. `cmp` failure (`cmp exit >= 2` → `ERROR: cannot compare ...`) was the only `ERROR:` line
   printed to **stdout**; every other `ERROR:` goes to stderr.
2. The drift-detection missing-file `ERROR:` lines (`missing from repo scripts dir`,
   `missing from HERMES scripts dir`) also landed on stdout, so the documented stdout
   contract (`OK`/`WARN`/`PLAN`/`APPLIED`/`REFUSED`/summary only) was aspirational.
3. The round-2 note claimed a directory destination was "normally masked by `cmp` rc>=2".
   False: the drift loop only reaches `cmp` when both sides pass `[ -f ]`, so a directory
   destination never reached `cmp` at all — it was silently invisible as drift, and
   reconcile then moved the temp file *inside* it.
4. The `-d`/`-L` guards in the reconcile copy loop had no test coverage.
5. A test named "destination is a directory -> …" asserted `[ ! -e "$REPO/$DIRDEST/$DIRDEST" ]`,
   a path the bug would never create — it could never fail.

One NIT was **rejected with evidence**: the note's 2026-10-29 `rc=3` record is correct.
Exit code 3 = content drift is documented in the script header and `--help`
(0 clean / 1 error / 2 jobs.json / 3 drift / 64 usage); the reviewer assumed the contract
ended at 1. Recorded in the note so the next reader does not re-raise it.

## What changed

- `scripts/check-ops-drift.sh` — the three stdout-dwelling `ERROR:` lines now go to stderr
  (`>&2`); exit codes unchanged. Every `exit 1` in the reconcile loop reached through a
  validation guard (unsafe name, `-L`, `-d`) now also emits exactly one
  `REFUSED: validation — see stderr` line on stdout, so dry-run refusals obey the same
  contract as `--apply` refusals.
- `scripts/test-check-ops-drift.sh` — added: dry-run reconcile onto a symlink destination
  asserts `REFUSED: validation — see stderr` and that the link target is byte-identical;
  directory-at-repo-path cases (apply and dry-run) assert exit 1, no `APPLIED:`, directory
  preserved, and no `*.tmp.*` litter. Removed the dead assertion and a filler duplicate.
- `docs/notes/2026-10-14-ops-drift-loop.md` — corrected the "masked by `cmp`" mechanism,
  documented `rc=3`, and recorded the honest limit: the `-d`/`-L` loop guards are
  defence-in-depth and **unreachable through the drift path** (drift requires `[ -f ]` on
  both sides), so they are covered by the symlink refusal test plus code review, not by an
  integration test that pretends to hit them.

## Lessons worth keeping

- A passing test that asserts a path the bug cannot create is worse than no test: it reads
  as coverage. Assert the observable contract (`rc`, absence of `APPLIED:`, no temp litter).
- Defence-in-depth guards that the production path can never reach must be labelled as such
  in the note. Writing a test that "covers" them by exercising a different failure is
  fabrication with extra steps.
- When a review NIT contradicts the script's own documented exit codes, check the header
  and `--help` before editing the note — rejecting a finding with evidence is part of the
  gate, not a violation of it.
- `opencode` is not on the cron PATH; it lives at `~/.opencode/bin/opencode`. Its
  non-interactive form is `opencode run "$(cat spec.txt)"`, and a spec that names the exact
  assertion text gets a faithful test the first time.
